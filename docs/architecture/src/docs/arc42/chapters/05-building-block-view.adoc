==== CLI / Developer Interface

Responsibilities:

* project initialization and attachment;
* change creation and inspection;
* explicit execution of workflow steps;
* approval/rejection/exception commands;
* inspection of evidence, diffs, policy violations and memory;
* provider/project configuration;
* status and audit navigation.

The developer interface is a persistent, retained-context shell. A
Praetor-owned hierarchical command tree scopes commands by mode and is the
single source for dispatch, help, descriptions, usage, completion, and
contextual `?`. The session owns a separate presentation-navigation mode
stack; entering or leaving a mode does not change Project identity, Change
state, or workflow state.

The readline adapter owns terminal key handling, history, buffer/cursor
redisplay, and completion rendering only. The CLI is an inbound adapter. It
must not contain domain logic that cannot also be invoked by another future
adapter such as an API, IDE extension, or desktop UI.

==== Workflow Engine

The Workflow Engine is the orchestration authority. It evaluates the current Change state, workflow definition, policies, approvals and generated artifacts to determine which operations are allowed.

It MUST NOT encode provider-specific behavior. It coordinates ports such as Agent Execution, Repository, Verification, Memory, Audit and Approval.

==== Change Domain

The Change aggregate preserves intent and state. Candidate concepts include:

* ChangeId
* ChangeType
* ChangeIntent
* ChangeState
* ChangeSurface
* RiskClassification
* Specification
* Plan
* ExecutionAttempt
* VerificationResult
* ReviewResult
* Approval
* Exception
* Postmortem

==== Specification Engine

Transforms normalized intent and repository context into an explicit behavioral/technical specification or validates a human-provided spec. It is responsible for specification completeness and traceability, not implementation.

==== Policy Engine

Evaluates executable engineering invariants. It must support deterministic checks and may use AI-assisted classification only where deterministic evaluation is insufficient. Policy decisions are system decisions with evidence.

Policy families include clean code, testing, architecture, security, dependency management, change surface, backward compatibility, performance, observability, error handling, API contracts and database changes.

==== Repository Intelligence

Builds and incrementally updates the repository model. It is responsible for discovery, symbol/dependency relationships, test topology, history-derived context, impact evidence and knowledge-gap detection.

The executable M0.3 subset is intentionally smaller: the local Git adapter
captures repository root, `HEAD`, clean/dirty status, tracked path inventory
and a source-state integrity digest. It does not persist an index or implement
symbol, dependency, semantic, or history-mining intelligence.

==== Impact Engine

Computes the likely blast radius of a requested change and produces an expected/possible/protected surface. It provides evidence to Policy Engine and Sandbox Runtime.

In M0.3, candidate selection is deterministic and explicit: developer-supplied
file paths are normalized and verified against the SourceSnapshot tracked
inventory. Exact file-level actual paths can then be accepted or rejected
against the ApprovedScope. Richer inference remains future capability.

==== Agent Router

Selects an AI provider/model adapter based on the role's required capabilities and governance constraints. Routing dimensions include:

* structured-output support;
* context capacity;
* tool capability;
* code/reasoning characteristics;
* execution mode;
* cost/latency policy;
* provider trust level;
* data classification;
* organizational allow/deny policy.

The Agent Router is not part of the M0.5 executable subset. M0.5 performs
exact configuration/session selection only; it does not rank, route, fall
back, or choose providers by capability, trust, classification, cost, or
latency.

==== AI Provider Port and First Adapter

The executable M0.5 AI Provider Port describes one implementation attempt in
provider-independent Praetor semantics. It accepts a normalized
`ExecutionRequest` tied to an existing active ProposalWorkspace and returns a
normalized `ProviderResponse`. The response is untrusted execution
provenance; Git-derived workspace state is authoritative.

The composition root explicitly registers exactly one adapter, `codex-cli`,
and resolves the active provider and optional provider-scoped model by exact
name. Adapter and `OpenAI` vendor metadata remain distinct. `codex-cli` shapes
the request, performs bounded local version/capability preflight, invokes
non-interactive `codex exec` in the ProposalWorkspace, bounds and parses JSONL
output, and normalizes failures.
No Codex CLI process types, flags, or event structures cross the port. A
future OpenAI HTTP/SDK adapter is a separate implementation of the same port.

==== Sandbox Runtime

Provides isolated execution for agent-proposed source changes. Preferred strategies include isolated worktrees and/or containers. The main working tree is not the default direct write target.

The executable M0.4 subset creates a detached Git worktree outside the
canonical repository at the exact clean `SourceSnapshot` revision. A
canonical-source guard compares `HEAD`, working-tree state, tracked inventory
and source-state digest before and after workspace creation, controlled test
mutation, patch extraction, surface classification and cleanup. The local Git
adapter extracts a deterministic binary-capable patch plus a NUL-delimited
changed-path inventory, and the application service compares the complete path
set with the existing `ApprovedScope`.

This subset is source/workspace isolation, not process, network, container,
VM, credential, or hostile-code containment. M0.4 has no provider or AI
executor. M0.5 adds only the explicitly selected provider adapter operating in
that workspace; it does not turn the worktree into a security sandbox or a
generic command runner.

==== Verification Engine

Coordinates deterministic validators and emits normalized evidence. Individual analyzers/test runners are adapters.

==== Review Engine

Coordinates independent AI review roles and deterministic evidence summaries. It must record disagreements rather than flattening them into a false consensus.

==== Memory Engine

==== Audit Ledger

Receives append-oriented events for commands, runs, inputs, outputs, model/provider identity, hashes, state transitions, approvals, memory promotions, policy outcomes and exceptions.

==== Project Registry

Associates a project identity with its source repository, memory repository and local configuration without requiring the source repository itself to contain a Git submodule or vendor-specific metadata.

=== Ports

The initial architectural port catalog includes:

[cols="1,3",options="header"]
|===
|Port |Purpose
|AI Provider Port |Execute an explicitly selected role-scoped provider request in a ProposalWorkspace and expose descriptive capabilities through provider-independent types
|Repository Port |Read source state, diff, history, symbols and working-copy metadata
|SCM Port |PR/review/remote repository operations
|Issue Tracker Port |Retrieve normalized change intent
|Static Analyzer Port |Run deterministic code analysis
|Test Runner Port |Run selected tests and return structured outcomes
|Security Scanner Port |Run SAST/dependency/container checks
|Secret Scanner Port |Prevent secrets from entering source/memory artifacts
|Artifact Store Port |Persist change artifacts and evidence
|Memory Store Port |Read/write canonical memory records through governed operations
|Memory Index Port |Query local projections and full-text index
|Embedding Port |Optional semantic indexing/retrieval
|Policy Port |Evaluate engineering/governance policy
|Sandbox Port |Create and remove an isolated proposal workspace
|Patch Port |Extract the patch and machine-safe changed-path inventory from an isolated workspace
|Telemetry Port |Emit metrics/traces/logs under policy
|Identity Port |Resolve actor and authority
|Approval Port |Record/retrieve human approvals and exceptions
|===
