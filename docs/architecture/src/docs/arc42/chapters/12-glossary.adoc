== Glossary

[cols="1,3",options="header"]
|===
|Term |Meaning
|Accepted Change |A proposed code modification that passed required validation/approval and is allowed to affect canonical source state.
|Adapter |Concrete integration implementing a core port for an external technology/provider.
|Agent |Role-scoped AI executor. An agent is not an authority and is not synonymous with a provider.
|Agent Router |Component that maps role requirements and governance constraints to a compatible provider/model adapter.
|Approval |Explicit authorization from an actor with the required authority for a state transition or exception.
|ApprovedScope |Separately governed authority identifying where a proposal may write; RepositoryModel, impact, and risk cannot expand it.
|Artifact |Immutable versioned record and payload belonging to one Project and Change; its opaque ArtifactId is distinct from its content digest.
|Audit Ledger |Append-oriented event history describing commands, runs, artifacts, decisions, actors and hashes.
|Canonical Memory |Durable accepted memory records representing project/organization engineering knowledge.
|Change |Primary auditable work aggregate representing one requested software evolution/fix.
|ChangeId |Opaque project-scoped identifier; `(ProjectId, ChangeId)` is durable Change identity and neither value is derived from source paths or Git state.
|Change Surface |Expected, possible, protected, uncertain, and actual repository elements associated with a Change; classification is distinct from write authority.
|ChangePlan |Immutable ordered declarative engineering contract over one exact Specification revision, with stable PlanId, monotonic PlanVersion, deterministic PlanDigest, and one ArtifactId per revision.
|Context Pack |Task-scoped projection of repository/memory/policy knowledge assembled for one AI role invocation.
|Developer Sovereignty |Principle that the engineering process and authorized humans retain final authority over consequential actions.
|Evidence |Structured result supporting a claim or state transition: tests, scans, diffs, analysis, approvals, etc.
|Engineering Knowledge Surface |Cross-cutting source-linked read model under an owning artifact/specification/memory milestone; never a parallel source of truth or an independent milestone.
|Institutional Engineering Memory |Durable project/organization knowledge independent from an individual developer or AI provider.
|ImpactReport |Immutable Change-owned artifact recording exact model inputs, explainable impact, gaps, limits, and advisory RiskProfile.
|Knowledge Gap |Structured category, scope, reason, evidence, consequence, and resolution for unknown, excluded, unsupported, or insufficiently supported repository knowledge.
|Memory Candidate |Proposed knowledge record that has not yet become canonical memory.
|Memory Invalidation |Process of identifying previously valid memory whose supporting source/evidence changed.
|Memory Snapshot |Reference/fingerprint identifying the memory state used for an execution.
|Minimum Necessary Change |Optimization principle minimizing modification surface while satisfying correctness and constraints.
|Policy |Executable or governable engineering invariant that can allow, deny, require review/approval, or mark advisory findings.
|PlanApproval |Explicit immutable human authority bound to an exact current Plan, governing Specification, repository/impact context, PlanningGateDecision, and Change revision.
|PlanningGateDecision |Versioned pre-implementation planning decision with AUTO, APPROVAL, REVIEW, or FORBIDDEN outcome; distinct from post-patch PolicyDecision.
|OperationId |Opaque Project-scoped identity for a consequential operation, bound to an immutable request digest and durable result/recovery record.
|Port |Core-owned interface describing a capability required from external systems.
|Project |The logical governed software-engineering project. It is distinct from any repository checkout, worktree, Git remote, source revision, or repository location.
|ProjectId |Opaque generated logical identifier for a Project. It is persistent local identity and is not derived from filesystem path, repository location, Git remote, Git HEAD, Git history, repository fingerprint, or machine identity.
|Project Registry |Mapping between project identity, source repository, memory repository and configuration. The durable local registry lives outside the source repository and does not require repository mutation.
|Provider |External or local AI service/runtime supplying model execution.
|Provider Trust Level |Governance classification restricting which data can be sent to a provider.
|Provenance |Evidence of origin: actor, command, source commit, memory snapshot, model, input/output and hashes.
|Repository Archaeology |Initial/incremental discovery process that reconstructs structure, dependencies, testing, integrations and legacy constraints.
|Repository Model |Immutable Project-scoped, schema/build-key-bound repository graph with evidence, provenance, gaps, limits, and digest.
|Recovery Condition |Orthogonal operational diagnosis such as incomplete effect, divergence, corruption, or incompatibility; never a ChangeState.
|Role |Logical agent responsibility such as Planner, Implementer or Security Reviewer.
|RiskProfile |Advisory impact evidence with ordered LOW/MODERATE/HIGH or unordered epistemic INDETERMINATE; it is not approval, rejection, policy, or write authority.
|Run |One execution attempt of a workflow step/tool/agent.
|Sandbox |Architectural isolation boundary for proposed changes. The current implementation is Git worktree source/workspace isolation; stronger containment requires the gate of the approved capability that needs it.
|Software Change Provenance |Ability to reconstruct why/how/by-whom/with-what-context a code change was produced and accepted.
|SourceFingerprint |Composite comparable source condition covering exact tracked content/metadata and untracked status-name evidence under ADR-039.
|Specification |Immutable Change-owned requirements and constraints authority with stable SpecificationId, monotonic SpecificationVersion, deterministic SpecificationDigest, and one ArtifactId per revision.
|Specification Pack |Bounded structured authority rooted at one exact Specification plus immutable references; not a directory or recursive include hierarchy.
|State Machine |Explicit allowed progression of a Change rather than agent-controlled free-form progression.
|Workflow |Versioned engineering process defining stages, contracts, gates and allowed transitions.
|WorkflowSnapshot |Exact immutable workflow identity, version, schema version, YAML bytes, and SHA-256 integrity digest bound to a Change.
|===
