The runtime sits between the engineer and a set of external engineering/AI
systems. Current and future integrations are distinguished below; only the
implemented subset governs runtime behavior today.

=== In-Scope External Systems

[cols="1,2,2",options="header"]
|===
|External system |Purpose |Integration posture
|AI Providers |Planning, implementation, review, classification, semantic analysis |PARTIAL: provider-independent port and `codex-cli`; M3.0 routing and M3.1 multi-provider are TARGET
|Git Repository |Source state, diff, history, worktree/branch information |AS-IS local primary source-state reference; remote SCM operations are M3.2 TARGET
|Memory Repository |Durable project/organization engineering knowledge |TARGET: separate canonical storage; representation benchmark required
|SCM Hosting |PRs, commits, reviews, identities, repository creation |TARGET M3.2; GitHub is the first approved remote adapter direction
|Issue Tracker |Change intake and requirement context |TARGET M3.2 adapter
|Static Analysis Tools |Deterministic code checks |PARTIAL verification runner; M1.5/M4.1 adapters are TARGET
|Test Frameworks |Dynamic correctness evidence |AS-IS bounded direct-process execution; broader maturity is TARGET
|Security Scanners |SAST, secrets, dependency/container checks |TARGET M1.5 replaceable adapters
|Identity Provider |Human identity, role and approval authority |PARTIAL local interaction provenance; enterprise OIDC/SSO is TARGET M5.2
|Telemetry Backend |Execution metrics and traces |TARGET M3.3 optional policy-governed port
|===

=== Fundamental Trust Boundary

AI-provider output is **untrusted proposal data**. It does not become source code, project memory, policy, architectural decision, or accepted evidence merely because an agent emitted it. Every conversion into canonical state is mediated by system rules.

=== Project Registration Context

A project association is conceptually:

[source,yaml]
----
project_id: prj_opaque_generated_value
repository_root: /work/payment-service
memory_repository: future-association-only
----

The current registry maintains opaque Project identity and operational source
association. Memory association is target M2.0. A Git submodule is not required
and is not the default architectural interpretation.
