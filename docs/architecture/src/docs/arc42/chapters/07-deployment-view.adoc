=== Local Developer Deployment — Current and Target

The deployment model is local-first. Current elements are:

* one Go executable / CLI runtime;
* local source repository/workspace;
* isolated Git worktree for AI changes;
* the `codex-cli` provider adapter;
* local deterministic tools invoked as subprocesses/adapters.

Implemented local elements include the M1.2 per-Project rebuildable
RepositoryModel SQLite cache under XDG CACHE. Target elements include a
benchmark-selected rebuildable memory projection,
separate canonical Project Memory repository, remote SCM/evidence adapters,
and additional external or local AI providers behind the existing port. M1.1
uses one `change-store.sqlite3` per validated ProjectId under XDG DATA,
plus short Project-scoped mutation locks under XDG STATE. SQLite is local
Change/artifact/audit authority, not the separately benchmark-gated Project
Memory representation. No remote/shared Change store, memory serialization,
remote topology, or second provider is selected by this view.

ADR-041 reuses that existing Artifact Store for future canonical M1.3
Specification, ChangePlan, planning-gate, and PlanApproval artifacts. It adds no
repository-local authority, database topology, or deployment service.

The M1.2 cache is separate from Change authority and governed source. It is
safe to discard and rebuild; cache absence, corruption, or schema incompatibility
is an availability/performance condition and never grants freshness or removes
durable ImpactReports. Initial repository analyzers run in-process and read
bounded local inputs without network, credentials, repository scripts, or
repository-code execution.

Git worktree provides source/workspace isolation; it is not itself a security
sandbox. Recovery/local concurrency follow ADR-034 through ADR-037, while the
process/network/credential/resource boundaries required by quality/security
tools belong to the M1.5 decision gate.

=== Enterprise Deployment — Architectural Compatibility

A later Phase 5 deployment may introduce centralized organization memory,
policy distribution, identity/SSO, telemetry, provider gateways and hosted
audit retention. Hosted control-plane work is **CONDITIONAL/DEFERRED**, not an
inevitable implementation commitment.

The architecture should allow:

* enterprise OIDC/SSO;
* corporate provider gateways;
* organization-wide policy distribution;
* signed audit events/commits;
* central retention/classification controls;
* air-gapped/local-model operation;
* self-hosted SCM and scanners.

=== Failure Isolation

Provider failure must not corrupt canonical source or memory state. A failed model request or tool execution remains an ExecutionAttempt associated with the Change. Canonical mutation requires a later accepted transition.

=== Offline / Restricted Network Mode

Ports & Adapters and provider trust policy should support local-only operation where all data must remain inside a trust boundary. Exact offline packaging is TBD.
