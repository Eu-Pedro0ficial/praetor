== Architecture Constraints

=== Explicitly Decided Constraints

[cols="1,2,3",options="header"]
|===
|ID |Constraint |Consequence
|CON-001 |Implementation language is Go |Core runtime, CLI, domain and orchestration are implemented in Go unless an adapter has a justified external implementation.
|CON-002 |Layered architecture |Dependencies must remain understandable and organized into explicit responsibility layers.
|CON-003 |Ports and Adapters |External AI, Git/SCM, issue trackers, analyzers, runners, stores, identity and telemetry are reached through ports.
|CON-004 |SOLID, KISS, YAGNI and DRY |The implementation optimizes for maintainability and explicit design rather than speculative abstraction.
|CON-005 |No abbreviated identifiers when a full meaningful word exists |Examples such as `c` for `context` are forbidden. Naming quality is part of the coding policy.
|CON-006 |Developer remains sovereign |No AI provider becomes an authority that can bypass workflow or policy.
|CON-007 |Memory is independent from AI provider |Long-term knowledge survives provider replacement.
|CON-008 |Project memory is separated from the application source repository |The source repository does not have to be modified merely to adopt the tool.
|CON-009 |AI does not write canonical project memory directly |Agent output becomes a candidate that must pass validation and, where applicable, approval.
|CON-010 |AI implementation does not directly become accepted source |Changes should be isolated as patches/worktrees/sandbox outputs and become accepted only after validation.
|CON-011 |Workflow definitions use declarative YAML with schema validation |Workflow state/storage may be modeled independently from YAML, but the representation is not a custom DSL unless a later ADR and human approval justify the exception.
|CON-012 |Policy definitions use declarative YAML with schema validation |The Policy domain model stays representation-independent and simple by default.
|CON-013 |Go plugin loading is not the initial adapter strategy |Compile-time registration and composition-root selection remain the approved initial architecture.
|CON-014 |Git worktree is the initial source/workspace isolation mechanism |It is not described as a security sandbox; stronger isolation must await a separate spike and ADR.
|CON-015 |Provider trust and data-classification taxonomies are authoritative |Provider routing and governance reject disallowed provider/data combinations before transmission.
|===

=== Architectural Decision Closure Rule

A decision marked DEFERRED or BENCHMARK/SPIKE REQUIRED MUST NOT be silently resolved by an implementation task or AI agent.

When a milestone reaches the trigger for such a decision, implementation must stop, the benchmark/spike must be completed, an ADR or explicit architecture decision must be produced, human approval is required, and only then may implementation continue.

=== Deliberately Deferred Decisions

The following remain explicit design questions with known triggers and approval gates:

* hosted organization memory / persistence architecture;
* GUI or server control plane;
* semantic memory conflict detection beyond structural rules;
* canonical project memory serialization format benchmark.

=== Documentation Constraint

Documentation uses arc42 + C4 and is maintained as code through docToolchain. The current docToolchain wrapper pins a release rather than relying on an unversioned global installation.
