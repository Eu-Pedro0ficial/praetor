=== Normative Traceability Ledger

This appendix is the canonical inverse traceability ledger for Praetor. It
connects requirements, quality scenarios, architectural responsibilities,
pipeline stages, and quality/security capabilities to exactly one primary
milestone, supporting milestones, implementation, validation evidence, and
open decision gates. Roadmap prose may summarize this ledger but must not
maintain a competing ownership matrix.

==== Governance Rules

. Every `Must` requirement has exactly one primary owner. Supporting owners
  are permitted.
. Every first-class component and port has a lifecycle status and an owning
  milestone.
. Every reference pipeline stage remains represented.
. Every milestone declares its primary and material supporting requirements in
  the milestone contract; this ledger remains the complete inverse view.
. A milestone cannot become complete until this ledger contains stable
  implementation and validation references for its delivered rows.
. Milestone closure includes an arc42/C4 lifecycle-drift review.
. A new requirement receives an owning milestone or explicit approved
  deferral in the same documentation change.
. Removing a requirement or capability requires explicit supersession
  authority; deletion without trace is forbidden.
. References use stable package, file, command, or test identifiers rather
  than volatile line numbers.
. Inverse lookup is derived from this ledger. It is not copied into another
  independently maintained matrix.

The lifecycle vocabulary is:

* `AS-IS` — implementation matches the documented responsibility;
* `PARTIAL` — an executable subset exists and its maturity owner is named;
* `TARGET` — approved future capability with an owning milestone;
* `DEFERRED` — implementation is not approved until its decision gate closes;
* `SUPERSEDED` — retained for historical traceability only.

Run `python3 scripts/validate_traceability.py` from the repository root to
validate this ledger. The table body is deliberately one record per line so
the standard-library validator can parse it deterministically.
